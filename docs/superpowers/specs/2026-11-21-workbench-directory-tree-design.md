# 工作台左栏完整折叠目录树 — 设计

日期：2026-11-21 · 分支：`feat/detail-workbench` · 范围：仅 `cmd/webui/`

## 意图与理由

文件详情工作台的左栏目前只有当前目录的「已索引 / 未索引」两张平面列表，跨目录无路可走；文件列表页已经有一棵完整的折叠目录树（`GET /api/files` 全树 + `<details>` 折叠 + sessionStorage 折叠记忆 + `/api/files/expand` 懒加载未索引）。本次把同一棵树装进工作台左栏，并**直接替换**目录列表（已与用户确认，不做共存模式），机制按**共享组件**单源（已与用户确认方案 A，列表页同步改为调用组件）。

## 目标

- 新共享 Alpine 组件 `directoryTree`（`static/js/core/tree.js`，base.html 挂载）：承载全树加载、逐级排序、`<details>/<summary>` 渲染、折叠状态持久化（键沿用 `tagfile_tree_open:<path>`，两页互通）、未索引子项懒加载、文件行构造（图标/完成态/AI 徽章/标签数/大小）。
- 组件参数恰好三个：① `onFileClick(node)`——列表页维持 `<a href>` 整页导航、工作台调用既有 `navigateToFile` 就地换文件且不丢流水线状态；② `picks` 勾选列开关（仅列表页开，含批量识别的勾选/同步/事件委托逻辑）；③ `currentPath` 高亮（仅工作台传）。
- 工作台侧栏：每次换文件（含推荐流水线 `nextFile`）自动展开祖先目录、高亮当前文件并 scrollIntoView；组/标签/完成态操作只更新当前行 DOM，不整树重取。
- 文件列表页：行为逐字节不变，靠既有测试与回归验证盯住。

## 非目标

- 不动任何后端 API（`/api/files`、`/api/files/expand`、详情接口原样复用）。
- 不做树的搜索、拖拽、虚拟化等新能力。
- 不改推荐流水线与打标面板。

## 反目标

- 列表页的批量识别勾选、排序、懒加载在重构后出现任何行为漂移。
- 工作台点树中文件导致整页刷新、推荐状态（recSeen/scope/sessionStorage）被重置。
- 同一棵树的渲染/开合逻辑在两个文件里各存一份。

## 约束

- Alpine 无递归模板，沿用两页现状的 JS 字符串渲染 + `x-html`；渲染后挂 toggle 监听的 `afterRender` 模式保留。
- 仅改 `cmd/webui/`；变更记入 `docs/CHANGELOG_webui.md` 新条目 5.21.0 并同步 bump `WebuiVersion`（AGENTS.md 规矩，同一 commit）。

## 已定决策（用户）

- 树直接替换当前目录列表，不共存。
- 实现走方案 A：抽共享组件，两页单源。

## _builder 裁量（我的默认，反对请说）_

- 工作台保留 `dir-header`（显示当前文件所在目录）与现有排序控件（键 `tagfile_detail_*` 不变），排序作用于树逐级节点；字段语义与列表页一致。
- 「加载中/出错」空态沿用工作台现成的占位面板语言；树数据在推荐模式下随 `nextFile` 首次加载后即复用，不为每个文件重取全树。
- 当前文件行的乐观更新：打标数、完成态、AI 徽章三处经 `data-path` 定位行内直改，与 `mirrorFileField` 同一时机触发。
- 折叠记忆与列表页共享同一 sessionStorage 命名空间；工作台自动展开祖先时同样写这份记忆（与手工展开无差别）。
