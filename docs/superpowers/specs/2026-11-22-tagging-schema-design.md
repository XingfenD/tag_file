# 打标场景 Schema 设计

**Goal:** 在工作台上以可配置的「schema 视角」结构化打标（如评级只出星级），产物物化进现有标签体系，全链路兼容。

**日期:** 2026-11-22 · **讨论:** 会话裁决（方向二 → 落法 B → 绑法一 → 三种字段）

## 意图与为什么

现在工作台的打标是自由式的：全量标签下拉 + 可选值，任何文件任何标签都能打，没有「场景」概念。用户希望像数据库 schema 那样封装多种打标场景——打开一个文件，从多个 schema 的视角贴标签：评级那一格只能点 1–5 星，视角那一格只能勾既有的几种，各归各的，打不歪。

关键取舍已在讨论中裁决（见 Approaches）：schema 是独立实体，但值不落独立表，而是物化成普通标签，换取搜索/导出/计数/AI 审核零改动。

## 目标

- **schema 可配置**：独立实体 = 名字 + 有序字段列表；新建/编辑/排序/删除在专门的「场景管理」导航页完成。
- **三种字段类型**（第一版全量）：
  - **单选枚举 single**：绑定一个已有标签；取值域 = 该标签的 `TagValue` 字典。渲染 widget 可配 `select`（默认）或 `stars`（星级只是单选的渲染皮肤，不是新类型）。`TagValue` 无排序列，stars 按 value_id（插入序）渲染；值数 ≠5 或含非数字时管理页给提示，不新增排序配置。
  - **开关 bool**：绑定一个已有标签；开 = 打无值标签，关 = 删标签。面板状态读该标签行的存在性，不另存真相。
  - **多选 multi**：绑定一个父标签；候选 = 其子标签；勾中即打对应子标签，取消即删。只动子标签行，父标签自身的行永远不碰。
- 允许绑定空字典（single/bool）或无子节点（multi）的标签：面板显示「无候选」，管理页标警告不拦截。
- **显式绑定**：字段必须绑定标签树里存在的标签；管理页提供「标签还不存在？就地创建」的快捷入口，走现有 `tag.Service.AddTag`，不开第二条写入路径。一个标签只允许被一个字段绑定，保存时服务层校验，重复绑定拒绝。
- **物化**：写入落 `TagGroupTag`（文件默认组）。schema 只是便捷写入口，无排他性：自由打标下拉不过滤被绑定标签，后写者胜。
- **接管式覆盖**：single/bool 保存时删除该绑定标签在默认组的全部行、只写面板当前值（multi 删全部子标签行、写勾选集）；自由打标或 AI 审核落进同一标签的行会在下次 schema 保存时被合并掉，这是裁决后的预期行为。
- **写路径**：新建 service 方法在单事务内做 repo 级 diff（缺则加、多则删、同步维护 `TagCnt`），对齐 `TagFile/UntagFile` 的查重与计数语义但不复用它们——两者对 no-op 抛错，改动即生效的控件不能因「本来就关着」弹错误条。
- **工作台呈现**：媒体区与标签组表格之间插入「打标场景」卡片区，每个 schema 一个面板、每字段一行控件；改动即生效（每个控件一次落库），无整表提交。所有 schema 对所有文件可见。
- **绑定失效可见**：绑定的标签被删后，工作台该字段显示绑定失效提示，管理页可重绑；不静默吞掉。

## 非目标

- 自由文本字段（绕过 TagValue 字典往标签池灌野值，与建 schema 的秩序方向相反）。
- schema 值的存储层唯一约束、按文件类型/目录的范围圈定、AI 提示词按 schema 生成。
- schema 值作为独立查询/导出维度（物化标签天然被现有搜索与 SQL 导出认识）。
- 文件列表页的 schema 列。
- 删除 schema 时清理其物化出的标签与已打值（只删定义）。

## 反目标

- 出现第二套标签值真相（schema 不得有自己的值表绕过 `TagGroupTag`）。
- 破坏现有自由打标链路（工作台原加标签入口、标签组、审核页都不动）。

## 数据模型

AutoMigrate 增两张表（无 raw SQL 迁移）：

```
tag_schemas     id PK · name uniqueIndex · description · sort_order
tag_schema_fields id PK · schema_id FK(index) · label ·
                  type enum('single','bool','multi') ·
                  widget varchar nullable(仅 single 有意义: 'select'|'stars') ·
                  bind_tag_id FK(index) · sort_order
```

- single 的值域、multi 的候选、bool 的语义全部从绑定标签在现有树里的形态推导，不落冗余配置——字典/子标签改了，schema 面板自动跟着变。
- 服务层新增 `internal/service/schema`（CRUD + 两个读视图：管理页列表、工作台面板状态）与一个物化写接口（按字段应用值）。

## 工作台读路径

面板初始态 = 一次查询该文件默认组里 `bind_tag_id`（multi 为其子标签集）命中的 `TagGroupTag` 行；single/bool 取行值、multi 取存在集。绑定标签若有多行（自由打标/AI 途径落入），single 面板取 value_id 最大（最新写入）一行的值展示，下次 schema 保存整体接管。落库成功后局部刷新该面板（沿用详情工作台现有的静默刷新/指纹机制，避免整页闪烁）。

## Approaches（讨论中已裁决）

| 决策点 | 选 | 否 | 理由 |
|---|---|---|---|
| schema 与标签树的关系 | 独立实体，自定义字段（二） | 寄生在分类上的配置（一） | 用户要「字段」不是「筛选视图」 |
| 值的落点 | 物化成标签（B） | 独立值表（A） | 全链路兼容免费；代价（存储层约束丢失）由 service 替换语义补 |
| 字段→标签映射 | 显式绑定已有标签（一） | schema 自动物化命名空间（二） | 标签树保持唯一事实源，不随 schema 编辑史长垃圾 |
| 字段集合 | 单选(含星级)/开关/多选 | 自由文本 | 三种都能在现有标签语义里干净落位 |
| 与自由打标的冲突 | 接管式覆盖，schema 无排他（a） | 从自由下拉排除绑定标签（c）、各行其是保留多行（b） | schema 定位就是便捷写入口，后写者胜，不需要排他秩序 |
