# Ollama 视觉识别自动打标 — 设计文档

日期：2026-11-13
状态：已与需求方确认核心决策，待评审

## 1. 意图与背景

tagfile 目前的标签全靠人工打：文件 scan 注册后，用户逐个文件选分类、选标签。对大量图片/视频来说，这一步最耗时。

本功能引入用户自行部署的 Ollama 视觉模型：对已注册的图片/视频做画面内容识别，产出结构化标签建议，经人工审核后落入现有标签体系，从而直接复用系统现有的标签检索能力（OR/AND/NOT 组合搜索）按内容找文件。

核心原则：**模型只提建议，人决定入库**。识别完成不等于打标完成，中间有一道人工闸门。

## 2. 目标

- 在 WebUI 上对一批已注册的图片/视频文件批量发起 AI 识别。
- 图片直接喂给 Ollama 视觉模型；视频先抽帧、按帧间差异过滤近似帧，留下代表性帧再喂模型。
- 模型输出结构化标签建议：优先命中现有标签库（提示词中携带现有分类与标签树），允许产出新词。
- 所有建议（含命中旧标签的）进入待审队列；人工逐条审核、可修改，确认后才建标签并关联文件。
- 后台任务化处理，页面可见每个任务状态（排队/处理中/完成/失败），失败可重试。

## 3. 非目标

- 不做 CLI 入口，仅 WebUI。
- 不保存模型对画面的描述文字——描述只是中间产物，只留标签。
- 不做语义/向量检索，检索仍走现有标签搜索。
- 模型不生成标签值（TagValue / TagGroupTag.Value），值由用户审核后按需手动添加。
- 不做音频内容分析、人脸识别等额外能力。
- 不自动应用任何标签，哪怕模型置信度很高。

## 4. 反目标（做成了也算失败）

- 模型输出未经审核直接写入标签库，污染标签词表。
- 并发调用模型打爆显存/服务。
- 长耗时识别阻塞 WebUI 请求或页面。
- 任务失败被静默吞掉，用户不知道哪些文件没处理。

## 5. 已确认的决策（需求方拍板）

| 决策点 | 结论 |
|---|---|
| 入口 | WebUI，批量发起（目录/多选文件） |
| 模型 | 用户自部署的 Ollama 视觉模型，地址与模型名可配置 |
| 视频处理 | 抽帧 + 帧间差异过滤，代表性帧喂模型 |
| 标签词表 | 优先从现有标签库选；允许新词，新词必须人工审核 |
| 审核范围 | 全部建议都进待审，人工全部过一遍再入库 |
| 描述文字 | 丢弃，只留标签 |
| 最大帧数 | 可配置，默认 10 |
| 标签库规模 | 小（几十到两三百个标签），全量分类+标签树进提示词可行，无需分类预选 |
| 完成标记 | 拓展出独立的 AI 打标状态：进行中 / 完成（待审）/ 通过（审核完）；`File.TagDone` 保持手动，「AI 打标通过」后才由用户手动标记完成 |
| Ollama 鉴权 | 不需要，直连，仅配置地址 + 模型名 |

## 6. 默认选择（设计者决定，需求方未反对，可否决）

- **抽帧**：依赖本机 ffmpeg（已确认本机有 8.0.1）。按固定间隔抽帧（默认 1 帧/秒），用帧间差异（直方图或感知哈希）过滤近似帧，最多保留 10 帧。抽帧间隔、差异阈值、最大帧数均为 config 项。
- **模型输出格式**：约定 JSON，每条建议 = 分类（从现有分类中选）+ 标签名。提示词携带现有分类列表与标签树。不要求模型给父标签、置信度、描述。
- **审核页**：全局待审队列页面。每条建议可：改名、换分类、合并到已有标签、拒绝；支持批量通过。通过时才真正创建标签（新词）并关联到文件。
- **任务机制**：任务记录存 SQLite + 进程内单 worker 顺序处理（避免并发打爆显存）。前端轮询任务状态。失败任务可重试。
- **处理范围**：仅已注册的图片/视频文件（按扩展名判断）；未注册文件提示先 scan。
- **配置**：Ollama 地址、模型名及抽帧参数全部走现有 config 服务（`internal/service/config`，key-value），在现有配置页管理，不新造配置机制。
- **重启行为**（评审后设计者决定）：进程重启时，处理中（running）任务标记为失败（原因「重启中断」，可手动重试）；排队中（queued）任务在 worker 启动后自动继续处理。
- **重复发起**（评审后设计者决定）：批量发起时默认跳过已有待审建议或已完成识别的文件；用户可对单文件显式「重新识别」，此时清掉该文件旧的 pending 建议后重新入队。

## 7. 系统现状与约束（实现必须遵守）

- Go 1.24.1，模块 `github.com/XingfenD/tag_file`。WebUI 为 Gin + 内嵌模板 + `/api/...` JSON 接口（统一 `{"ok":bool,"msg":"..."}` 信封）。
- SQLite via GORM，DB 在 `.tagfile/tagfile.db`，schema 只走 `AutoMigrate`，禁止裸 SQL 迁移。
- 唯一性（分类名全局、标签名同分类内）在 service 层强制；新标签创建必须走现有 tag service，不得绕过。
- 打标走 `internal/service/file/tag.go` 的 `TagFile(filePath, tagID, tagValue)`（或标签组路径），`File.TagCnt` 冗余计数必须经 `IncrementTagCnt`/`DecrementTagCnt` 维护。
- Repository 为链式 builder，一个操作一个文件（`repo.List().ByXxx().Exec()`）。
- 现有模型：`File`（file_id/file_path/file_type/tag_cnt…）、`Tag`（category_id/parent_id/tag_name）、`TagCategory`、`TagGroup`/`TagGroupTag`、`Config`。见 `internal/model/`。
- 模板 `{{define}}` 不能嵌套；前端 JS 按页面拆分在 `cmd/webui/static/js/`，共享 `api.js` fetch 封装。
- 无 linter、无 CI；测试 `make test`。
- 提交规矩：不在 master 提交；核心改动记 `docs/CHANGELOG.md` 并 bump `internal/constant.CoreVersion`，WebUI 改动记 `docs/CHANGELOG_webui.md` 并 bump `cmd/webui/constant.WebuiVersion`，同 commit 完成；CHANGELOG 同条目英文行+中文行相邻。
- 外部依赖：ffmpeg（抽帧，外部进程调用）；Ollama HTTP API（外部服务，地址可配置，可能远程）。

## 8. 方案轮廓（方向性，细节留给实现者）

数据模型（新增两张表，AutoMigrate）：

- **识别任务表**：每文件一条，记录文件、状态（queued/running/done/failed）、错误信息、时间戳。
- **标签建议表**：每文件每建议一条，记录任务/文件、建议分类名、建议标签名、匹配到的已有 tag_id（可空）、审核状态（pending/approved/rejected）、审核后的最终分类/标签名。

流程：

1. WebUI 选择目录/多文件 → 创建任务入队（仅已注册图片/视频）。
2. 单 worker 顺序消费：图片直接读文件；视频 ffmpeg 抽帧 → 差异过滤 → 截断到最大帧数。
3. 调 Ollama 视觉 API（提示词含现有分类+标签树 + 约定的 JSON 输出格式），解析建议写入建议表，全部 pending。
4. 待审页面展示队列；用户逐条/批量处理：通过（新词先经 tag service 建标签，再关联文件并维护 TagCnt）、改名/换分类后通过、合并到已有标签、拒绝。
5. 同一新词出现在多个文件时，审核入库需去重（复用已建标签，不重复创建）。
6. 任务状态 API 供前端轮询；失败可重试（重试重新识别，旧 pending 建议的处理策略由实现者定，需避免重复建议堆积）。

文件级 AI 打标状态（需求方确认的新增能力）：

- 状态流转：**进行中**（任务排队/处理中）→ **完成**（识别结束、建议待审）→ **通过**（该文件全部建议审核完毕，无论通过或拒绝）。识别失败停留在可重试态，不算完成。
- 状态在文件树/文件详情可见（与现有 TagDone 徽章并列展示）。
- `File.TagDone` 语义不变、仍纯手动；「AI 打标通过」之后是否标记完成由用户自己决定。
- 状态可由任务表 + 建议表推导，也可落冗余字段，由实现者定，但必须与审核操作保持一致。

## 9. 留给实现者的决定

- 提示词具体措辞与 JSON schema 细节、模型输出解析失败的容错。
- 帧间差异算法选型（直方图/感知哈希）与阈值默认值。
- 两张新表的字段/索引细节、API 端点命名、前端页面布局与轮询间隔。
- 图片/视频扩展名清单、抽帧临时文件的存放与清理。
- 任务并发数是否开放配置（默认 1）。
- 审核页交互细节（批量选择的粒度、按文件分组还是平铺）。

## 10. 验收口径

- 批量发起后不阻塞页面，任务状态可见、失败可见可重试。
- 任何模型输出在人工通过前不出现在标签库和文件标签中。
- 审核通过后，用现有检索（如 `search tag --and`）能按新标签找到对应文件。
- 视频抽帧参数（含最大帧数）改 config 后生效。
- `make test` 通过；新增核心逻辑有测试覆盖。
