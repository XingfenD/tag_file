# Ollama 视觉识别自动打标 — 设计文档

日期：2026-11-13；2026-11-19 修订（逐帧识别 + 全片分镜覆盖抽帧 + 跨版本/容器约束）
状态：原始功能已实现并合入 master；2026-11-19 修订已与需求方确认，实施计划见 `docs/superpowers/plans/2026-11-19-ai-per-frame-scene-coverage.md`

## 1. 意图与背景

tagfile 目前的标签全靠人工打：文件 scan 注册后，用户逐个文件选分类、选标签。对大量图片/视频来说，这一步最耗时。

本功能引入用户自行部署的 Ollama 视觉模型：对已注册的图片/视频做画面内容识别，产出结构化标签建议，经人工审核后落入现有标签体系，从而直接复用系统现有的标签检索能力（OR/AND/NOT 组合搜索）按内容找文件。

核心原则：**模型只提建议，人决定入库**。识别完成不等于打标完成，中间有一道人工闸门。

## 2. 目标

- 在 WebUI 上对一批已注册的图片/视频文件批量发起 AI 识别。
- 图片直接喂给 Ollama 视觉模型；视频先抽帧（覆盖全片每一个不同分镜）、按帧间差异过滤近似帧，留下的代表性帧**逐帧**喂模型，建议跨帧合并去重（2026-11-19 修订）。
- 模型输出结构化标签建议：优先命中现有标签库（提示词中携带现有分类、标签树及标签预设值），允许产出新词；每条建议可带值（tag:value，如「裤子:黑色」），值同样进待审。
- 所有建议（含命中旧标签的）进入待审队列；人工逐条审核、可修改，确认后才建标签并关联文件。
- 后台任务化处理，页面可见每个任务状态（排队/处理中/完成/失败），失败可重试。

## 3. 非目标

- 不做 CLI 入口，仅 WebUI。
- 不保存模型对画面的描述文字——描述只是中间产物，只留标签。
- 不做语义/向量检索，检索仍走现有标签搜索。
- 不做音频内容分析、人脸识别等额外能力。
- 不自动应用任何标签，哪怕模型置信度很高。

## 4. 反目标（做成了也算失败）

- 模型输出未经审核直接写入标签库，污染标签词表。
- 并发调用模型打爆显存/服务。
- 把视频全部帧塞进一个模型请求——许多本地视觉模型只收单图或多图直接 OOM（2026-11-19 新增）。
- 抽帧只覆盖视频开头，尾段分镜永远识别不到（2026-11-19 新增）。
- 长耗时识别阻塞 WebUI 请求或页面。
- 任务失败被静默吞掉，用户不知道哪些文件没处理。

## 5. 已确认的决策（需求方拍板）

| 决策点 | 结论 |
|---|---|
| 入口 | WebUI，批量发起（目录/多选文件） |
| 模型 | 用户自部署的 Ollama 视觉模型，地址与模型名可配置 |
| 视频处理 | 抽帧覆盖全片分镜 + 帧间差异过滤，代表性帧**逐帧**喂模型（2026-11-19 修订，见 §5.1） |
| 标签词表 | 优先从现有标签库选；允许新词，新词必须人工审核 |
| 审核范围 | 全部建议都进待审，人工全部过一遍再入库 |
| 描述文字 | 丢弃，只留标签 |
| 标签值 | 必须要：value 是标签体系核心属性（如 裤子:黑色、袜子:黑色长袜），模型输出 tag:value，值随建议一起待审、可修改 |
| 新值入库 | 审核通过的新值只落到文件关联（TagGroupTag.Value），不写入预设值列表（TagValue）；预设值字典保持人工维护 |
| 最大帧数 | 可配置，默认 10 |
| 标签库规模 | 小（几十到两三百个标签），全量分类+标签树进提示词可行，无需分类预选 |
| 完成标记 | 拓展出独立的 AI 打标状态：进行中 / 完成（待审）/ 通过（审核完）；`File.TagDone` 保持手动，「AI 打标通过」后才由用户手动标记完成 |
| Ollama 鉴权 | 不需要，直连，仅配置地址 + 模型名 |

### 5.1 重设计补充决策（2026-11-19 对话确认）

原始实现把全部帧塞进一个模型请求、抽帧只取视频开头、近似帧过滤只与上一保留帧比对——三者都改掉：

1. **逐帧喂模型**：每帧一次调用（单图），各自超时；提示词每任务构建一次复用。图片文件天然单帧，行为不变。
2. **合并去重**：(分类, 标签, 值) 三元组精确去重保留首次出现；同 (分类, 标签) 存在非空值行时丢弃空值行（与出现顺序无关）；同标签不同值都保留，交审核人定。
3. **部分成功**：≥1 帧成功 → 任务完成，失败帧汇总写任务 Error；全部帧失败 → 任务失败，Error 记首条原因。建议集仍在末尾一次性原子写入，绝不给审核队列留半个建议集。
4. **近似帧过滤升级**：dHash 改区域平均采样（抗压缩伪影/脉冲噪声）；与**所有**已保留帧比对（治 A→B→A 切回重复）；不早停，去重后超最大帧数按时间均匀薄化；流式读盘，内存只留最终帧。
5. **抽帧两遍走、覆盖全片**：采样间隔 = max(配置间隔, 时长/(最大帧数×10))，配置键语义变为「最小间隔」；ffmpeg 内置硬切检测（scene>0.3，常量不进配置）把每个分镜切换点纳入候选；候选超预算均匀薄化；第二遍按时间戳定点抽取，分辨率压到 ≤768px。渐变/淡入淡出转场由周期采样层兜底，不追求完美分镜分割。
6. **超时随时长伸缩**：max(120s, 时长×2)，封顶 30min；ffprobe 缺失/取不到时长 → 记日志并退回配置间隔，不炸任务。
7. **ffmpeg 跨版本/容器**（需求方指令）：方案在不同机器上执行、最终都在容器里跑，**不预设任何本机 ffmpeg 版本**；只用 4.x 起就有的参数（白名单见实施计划 Global Constraints，刻意不用 5.1+ 的 `-fps_mode`）；运行容器必须自带 ffmpeg/ffprobe——现 Dockerfile 运行层是 `FROM scratch`（两者皆无、连 `/tmp` 都没有），需换 alpine + 发行版 ffmpeg 包。
8. **明确不做**：建议表加帧序号列、任务进度列、pHash、PySceneDetect/Python 依赖、分辨率可配置。

## 6. 默认选择（设计者决定，需求方未反对，可否决）

- **抽帧**（2026-11-19 修订）：依赖外部 ffmpeg/ffprobe，**不预设版本**（参数白名单见实施计划；容器镜像需自带）。两遍走：ffprobe 取时长 → 第一遍 `select`（首帧必选 + 自适应周期 + scene>0.3 硬切）+ `showinfo` 只产候选时间戳，间隔 = max(配置间隔, 时长/(最大帧数×10)) → 候选超预算均匀薄化 → 第二遍逐时间戳 `-ss` 定点抽取、`scale` 压到 ≤768px。超时 max(120s, 时长×2) 封顶 30min；ffprobe 失败退回配置间隔。抽帧间隔（默认 1 秒，语义为最小间隔）、差异阈值、最大帧数（默认 10）均为 config 项。
- **近似帧过滤**（2026-11-19 修订）：区域平均 9×8 dHash（纯 stdlib）；每帧与所有已保留帧哈希比对，任一距离小于阈值即丢；不早停，超最大帧数按时间均匀薄化；流式解码，内存只留最终入选帧。
- **识别**（2026-11-19 修订）：每帧一次模型调用（单图切片），逐帧解析；跨帧合并去重（§5.1 规则 2）后截断到单任务上限、一次性原子写入建议表；≥1 帧成功即完成（失败帧汇总进 Error），全失败才失败。
- **模型输出格式**：约定 JSON，每条建议 = 分类（从现有分类中选）+ 标签名 + 值（可选，自由文本）。提示词携带现有分类列表、标签树及各标签的预设值（TagValue），引导模型优先复用已有标签和预设值。不要求模型给父标签、置信度、描述。
- **审核页**：全局待审队列页面。每条建议可：改名、换分类、改值、合并到已有标签、拒绝；支持批量通过。通过时才真正创建标签（新词）并带值关联到文件。
- **任务机制**：任务记录存 SQLite + 进程内单 worker 顺序处理（避免并发打爆显存）。前端轮询任务状态。失败任务可重试。
- **处理范围**：仅已注册的图片/视频文件（按扩展名判断）；未注册文件提示先 scan。
- **配置**：Ollama 地址、模型名及抽帧参数全部走现有 config 服务（`internal/service/config`，key-value），在现有配置页管理，不新造配置机制。
- **重启行为**（评审后设计者决定）：进程重启时，处理中（running）任务标记为失败（原因「重启中断」，可手动重试）；排队中（queued）任务在 worker 启动后自动继续处理。
- **重复发起**（评审后设计者决定）：批量发起时默认跳过已有待审建议或已完成识别的文件；用户可对单文件显式「重新识别」，此时清掉该文件旧的 pending 建议后重新入队。

## 7. 系统现状与约束（实现必须遵守）

- Go 1.25.0（见 `go.mod`），模块 `github.com/XingfenD/tag_file`。WebUI 为 Gin + 内嵌模板 + `/api/...` JSON 接口（统一 `{"ok":bool,"msg":"..."}` 信封）。
- SQLite via GORM，DB 在 `.tagfile/tagfile.db`，schema 只走 `AutoMigrate`，禁止裸 SQL 迁移。
- 唯一性（分类名全局、标签名同分类内）在 service 层强制；新标签创建必须走现有 tag service，不得绕过。
- 打标走 `internal/service/file/tag.go` 的 `TagFile(filePath, tagID, tagValue)`（或标签组路径），`File.TagCnt` 冗余计数必须经 `IncrementTagCnt`/`DecrementTagCnt` 维护。
- Repository 为链式 builder，一个操作一个文件（`repo.List().ByXxx().Exec()`）。
- 现有模型：`File`（file_id/file_path/file_type/tag_cnt…）、`Tag`（category_id/parent_id/tag_name）、`TagCategory`、`TagGroup`/`TagGroupTag`、`Config`。见 `internal/model/`。
- 模板 `{{define}}` 不能嵌套；前端 JS 按页面拆分在 `cmd/webui/static/js/`，共享 `api.js` fetch 封装。
- 无 linter、无 CI；测试 `make test`。
- 提交规矩：不在 master 提交；核心改动记 `docs/CHANGELOG.md` 并 bump `internal/constant.CoreVersion`，WebUI 改动记 `docs/CHANGELOG_webui.md` 并 bump `cmd/webui/constant.WebuiVersion`，同 commit 完成；CHANGELOG 同条目英文行+中文行相邻。
- 外部依赖：ffmpeg/ffprobe（抽帧与时长探测，外部进程调用，**不预设版本**，只用 4.x 起就有的参数；运行容器需自带，测试环境缺失即 skip 集成测试）；Ollama HTTP API（外部服务，地址可配置，可能远程）。

## 8. 方案轮廓（方向性，细节留给实现者）

数据模型（新增两张表，AutoMigrate）：

- **识别任务表**：每文件一条，记录文件、状态（queued/running/done/failed）、错误信息、时间戳。
- **标签建议表**：每文件每建议一条，记录任务/文件、建议分类名、建议标签名、建议值（可空）、匹配到的已有 tag_id（可空）、审核状态（pending/approved/rejected）、审核后的最终分类/标签名/值。

流程：

1. WebUI 选择目录/多文件 → 创建任务入队（仅已注册图片/视频）。
2. 单 worker 顺序消费：图片直接读文件；视频 ffprobe 时长 → 两遍抽帧（全片分镜覆盖，§5.1 决策 5）→ 差异过滤 + 均匀薄化到最大帧数。
3. **逐帧**调 Ollama 视觉 API（每帧单图；提示词含现有分类+标签树 + 约定的 JSON 输出格式，每任务构建一次），逐帧解析、跨帧合并去重，一次性原子写入建议表，全部 pending；≥1 帧成功即完成，失败帧汇总进任务 Error。
4. 待审页面展示队列；用户逐条/批量处理：通过（新词先经 tag service 建标签，再经 `TagFile(path, tagID, value)` 带值关联文件并维护 TagCnt；值只写 TagGroupTag.Value，不写预设值 TagValue）、改名/换分类/改值后通过、合并到已有标签、拒绝。
5. 同一新词出现在多个文件时，审核入库需去重（复用已建标签，不重复创建）。
6. 任务状态 API 供前端轮询；失败可重试（重试重新识别，旧 pending 建议的处理策略由实现者定，需避免重复建议堆积）。

文件级 AI 打标状态（需求方确认的新增能力）：

- 状态流转：**进行中**（任务排队/处理中）→ **完成**（识别结束、建议待审）→ **通过**（该文件全部建议审核完毕，无论通过或拒绝）。识别失败停留在可重试态，不算完成。
- 状态在文件树/文件详情可见（与现有 TagDone 徽章并列展示）。
- `File.TagDone` 语义不变、仍纯手动；「AI 打标通过」之后是否标记完成由用户自己决定。
- 状态可由任务表 + 建议表推导，也可落冗余字段，由实现者定，但必须与审核操作保持一致。

## 10. 验收口径

- 批量发起后不阻塞页面，任务状态可见、失败可见可重试。
- 任何模型输出在人工通过前不出现在标签库和文件标签中。
- 审核通过后，用现有检索（如 `search tag --and`）能按新标签找到对应文件。
- 视频抽帧参数（含最大帧数）改 config 后生效。
- 视频识别覆盖全片：尾段分镜也能产出建议；硬切分镜不被粗采样间隔漏掉（2026-11-19 新增）。
- 每帧单独喂模型；单帧模型失败不炸整任务（完成 + Error 说明失败帧）（2026-11-19 新增）。
- 容器镜像自带 ffmpeg/ffprobe，视频识别在容器内可运行；无 ffmpeg 的测试环境集成测试 skip、`make test` 仍全绿（2026-11-19 新增）。
- `make test` 通过；新增核心逻辑有测试覆盖。
